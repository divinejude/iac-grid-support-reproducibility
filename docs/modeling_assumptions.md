# Modeling Assumptions For Journal-Grade Extensions

This framework separates the nominal model used inside the MPC from the higher-fidelity simulation plant. That split is intentional: the controller should not be evaluated only on the exact model it optimizes.

## OpenDSS Feeder And Frequency Model

The main simulation plant uses the IEEE 13-node test feeder through an OpenDSS snapshot adapter in `iac_dmpc/feeder.py`. Each MPC control interval edits the source-voltage magnitude, distributed feeder stress loads, and a distributed fleet of IAC load P/Q values, solves an OpenDSS power flow, and returns both fleet-weighted and worst bus-phase voltages.

The included benchmark files are in `examples/ieee13/`:

- `IEEE13Nodeckt.dss`
- `IEEELineCodes.dss`
- `IEEE13Node_BusXY.csv`

## TCL Fleet Allocation

The fleet is allocated using the common load-proportional approach used in distribution-level TCL aggregation studies:

- Read all original OpenDSS benchmark loads.
- Attach one controllable `Load.TCL_<original_load>` at each original load bus and phase connection.
- Assign each TCL load a share equal to `original_load_kw / sum(original_load_kw)`.
- Split aggregate IAC active and reactive commands using those shares.

Positive reactive support from the IAC fleet is modeled as negative OpenDSS load kvar, consistent with capacitive injection.

The adapter can also attach one `Load.Stress_<original_load>` at each original load bus. These loads are used only for feeder-local voltage stress experiments. This separates two physically different cases:

- Upstream source sag, where local reactive support has limited ability to restore the worst feeder voltage.
- Downstream feeder load growth, where local reactive support can materially improve the voltage profile.

## P/Q MPC Voltage Sensitivity

The full P/Q MPC mode estimates local voltage sensitivity online from OpenDSS finite differences:

- `dV/dP`: perturb aggregate TCL active power
- `dV/dQ`: perturb aggregate TCL reactive support

The optimizer uses this linearized voltage model over the MPC horizon while OpenDSS remains the nonlinear simulation plant. The full P/Q MPC mode uses the worst bus-phase voltage for network-aware Volt-Var triggering and for the finite-difference sensitivity metric. This keeps the controller convex and makes the model mismatch explicit.

Alternative studies can replace this allocation with AMI-derived household HVAC penetration, census-informed residential fractions, or Monte Carlo assignment across secondary service transformers.

OpenDSS is a quasi-static distribution power-flow engine, so feeder voltages are still solved as snapshot power flows. The frequency channel now uses the dynamic grid co-simulation contract in `iac_dmpc/grid_cosim.py`. The default scenario uses `CsvReplayDynamicBackend` with `data/dynamic_traces/lfc_replay_trace.csv`, generated by `generate_dynamic_frequency_trace.py`. The replay file includes:

- a no-IAC disturbance frequency trajectory;
- an IAC load-relief step-response kernel in Hz/kW;
- metadata-compatible timing for the 120 s to 420 s frequency event.

At runtime the backend superposes each controller's aggregate IAC load-relief changes onto the replayed dynamic response. This keeps the OpenDSS feeder adapter intact while replacing the reduced frequency block used in earlier drafts.

## ANDES Nonlinear Transient-Stability Validation

The script `validate_andes_transient.py` adds an offline nonlinear transmission validation check using ANDES. It starts from the ANDES bundled IEEE 14-bus dynamic benchmark, which contains GENROU synchronous-machine models, TGOV1 governors, excitation systems, and BusFreq measurement blocks.

The validation uses the same aggregate IAC active-power traces produced by the calibrated OpenDSS/IAC experiments:

- no support;
- active-only MPC;
- full P/Q MPC.

For each controller, the script creates a controller-specific Excel case and replaces the benchmark `Alter` sheet with timed TGOV1 auxiliary-power events. The active-power relief is converted from kW to per unit on a 100 MVA transmission base. A negative event represents the net under-frequency power imbalance, while positive IAC relief offsets part of that imbalance. ANDES then solves nonlinear time-domain simulation and the script extracts center-of-inertia frequency from the GENROU rotor-speed states.

This validation is stronger than the replay trace because the machines, governors, exciters, and network algebraic equations are solved by ANDES. It is still an offline benchmark validation, not a fully time-synchronized transmission-and-distribution co-simulation in which OpenDSS and ANDES exchange states at every integration step.

## Explicit T&D Dynamic Co-Simulation

The script `validate_td_cosim.py` implements an explicit T&D dynamic co-simulation check using the same ANDES IEEE 14-bus dynamic case and the OpenDSS IEEE 13-node feeder. The coupling loop is:

- Advance ANDES in short nonlinear TDS segments.
- Read the selected ANDES interface-bus voltage magnitude and angle.
- Scale the OpenDSS IEEE 13-node feeder source voltage by the current ANDES boundary voltage and the distribution source-sag profile.
- Solve OpenDSS with the current IAC P/Q trajectory and feeder stress loads.
- Return the feeder boundary active-power change to ANDES through the TGOV1 auxiliary-power input.

The default macro-step is 100 ms, with ANDES using 50 ms inner TDS steps. This is an explicit loose-coupling implementation. It provides distribution voltage feedback at every macro-step and is useful for validation figures, but it is not yet a converged multi-rate co-simulation with rollback, Picard iterations, or formal coupling-error control.

## Inverter Inner Loop

The inverter module represents dq current tracking as a first-order closed-loop system with configurable bandwidth. It includes:

- RMS current saturation
- DC-link current-derived limit
- P/Q apparent-power allocation
- Simple anti-windup correction

This is a reduced-order substitute for a switched or averaged inverter model. The validation scripts report the selected current-loop bandwidth and compare the grid-support command trajectory with the faster inner-loop dynamics.

The script `validate_averaged_converter.py` now supplies that averaged converter validation. It uses the full P/Q MPC command trajectory from the calibrated source-sag experiment and simulates a representative single-phase inverter at sub-millisecond resolution with:

- synchronous-reference-frame PLL dynamics;
- dq PI current control with bandwidth matched to `InverterInnerLoopParameters`;
- L-filter dynamics, grid-voltage cross-coupling, and PWM/computation delay;
- DC-link capacitance and limited DC source current;
- reactive-priority current limiting, voltage-command saturation, and anti-windup;
- a fast 0.75 pu voltage notch and -0.35 Hz frequency pulse superimposed on the MPC trajectory.

This validation reduces the earlier reduced-order inner-loop limitation by checking P/Q tracking, current, modulation, PLL, and DC-link behavior for the actual command trajectory. It is still an averaged model, so it does not replace hardware tests, switching-level EMT validation, semiconductor thermal checks, or protection validation.

The headroom experiments increase `S_rated`, `Q_max`, RMS current limit, and DC-link current limit together. This represents an explicitly oversized inverter package rather than an infeasible request for more kvar from the same semiconductor and thermal limits.

## Compressor And Thermal Model

The thermal model is a first-order RC room model with ambient heat gain, internal heat gain, and cooling capacity from the compressor. The compressor module adds:

- Active-power ramp-rate limit
- Speed-map approximation
- Minimum dwell-time constraint
- COP dependence on temperature lift and speed

The default parameters can be replaced by public measured NIST NZERTF data using `calibrate_from_nist_nzertf.py`. The script downloads minute-resolution measured HVAC, indoor environment, and outdoor environment data for the NIST Net-Zero Energy Residential Test Facility and extracts:

- occupied-zone room temperatures averaged into `indoor_c`
- `OutEnv_OutdoorAmbTemp`
- `HVAC_HeatPumpIndoorUnitPower`
- `HVAC_HeatPumpOutdoorUnitPower`
- HVAC supply and return air temperatures to classify cooling intervals

The fitted effective whole-building parameters are written to `data/nist_nzertf/calibrated_thermal_parameters.json` and can be applied with `python run_experiment_suite.py --thermal-calibration-json data/nist_nzertf/calibrated_thermal_parameters.json --output-dir experiments/nist_measured_calibrated`.

The public NIST minute HVAC file does not directly report delivered cooling capacity. The workflow therefore fits an effective COP and COP lift slope jointly with the RC parameters, then infers cooling capacity as `effective_cop * measured_heat_pump_power_kw`. These parameters should be interpreted as effective whole-building test-facility parameters, not as room-by-room envelope constants or occupied customer field measurements.

For comparison, the default parameters can also be replaced by public ResStock/EnergyPlus data using `calibrate_from_resstock.py`. The script targets NREL's public ResStock AMY2018 2024.2 release, downloads a representative Texas central-AC building, and extracts:

- `out.zone_mean_air_temp.conditioned_space.c`
- `out.outdoor_air_dryblub_temp.c`
- `out.electricity.cooling.energy_consumption`
- `out.load.cooling.energy_delivered.kbtu`

The fitted effective whole-dwelling parameters are written to `data/resstock/calibrated_thermal_parameters.json` and can be applied with `python run_experiment_suite.py --thermal-calibration-json data/resstock/calibrated_thermal_parameters.json`.

The lower-level calibration workflow in `iac_dmpc/calibration.py` also supports:

- Field or EnergyPlus CSV fitting with columns `time_s`, `indoor_c`, `ambient_c`, and `power_kw`.
- Optional `cooling_capacity_kw` data when EnergyPlus or manufacturer post-processing directly reports cooling capacity.
- Manufacturer performance-map COP fitting from ambient temperature, indoor temperature, electrical power, and cooling capacity.
- Compressor time-constant fitting from step-response data.

Because ResStock is a simulated building-stock product, it is an EnergyPlus-informed comparison calibration. The NIST workflow is measured test-facility validation, while broader occupied-home field validation still requires thermostat/indoor-temperature, submetered HVAC power, and preferably direct delivered-capacity measurements from customer residences.

## Sensitivity OPF Comparison

The script `compare_opf_sensitivity.py` solves a convex aggregate voltage-support OPF using OpenDSS finite-difference sensitivities, then applies the OPF result back to OpenDSS. This creates a direct comparison between the controller's local linear voltage approximation and the nonlinear feeder power-flow response. The latest comparison is written to `experiments/opf_comparison/opf_comparison.csv`.

## Noise, Delay, And Uncertainty

The measurement channel in `iac_dmpc/uncertainty.py` adds Gaussian sensor noise and fixed sample delay. Parameter sampling utilities perturb thermal resistance, capacitance, COP, and compressor time constant.

Supported uncertainty checks include:

- Monte Carlo parameter uncertainty
- Sensor-noise and delay sweeps
- Feeder impedance sensitivity
- Inverter current-limit stress cases
- Comfort-band sensitivity from +/-0.5 C to +/-3.0 C
